# Phase A–C 倒水数据采集

首轮采一条完整记录，从动作开始前录到回 Home，覆盖识别壶杯、抓壶、倒水和放壶。保留暂停、人工介入、重试和失败。单路 D435i 可以用来验证采集链路，正式训练导入要求腕部、全景、近景三路带时间戳的图像。

| 数据 | 保存内容 |
| --- | --- |
| 连续图像 | 原始分辨率、逐帧编号、设备采样时间和 PC 接收时间。 |
| ESTUN 实际反馈 | 连续六关节角和实际 TCP 位姿，记录单位、坐标系、工具编号和可用的运动状态。 |
| OmniHand 实际反馈 | 连续十轴原始位置、使能和错误状态，保留原始串口收发帧。 |
| 控制指令 | 机械臂目标、手势和轴目标、发送时刻及回复。有位置限幅时保留限幅前后值。 |
| 阶段与事件 | 识别、抓壶、倒水、放回、回 Home、人工介入、暂停、重试、故障及最终结果。 |
| 运行和标定 | 本次代码、配置、CRP、设备及 SDK 版本、相机内参、手眼标定、TCP 配置与完整日志。 |

每轮用同一个采集编号归档。各路按实际支持的频率采集，保存各自的时钟来源和 PC 接收时间。设备采样时间不可用时写 `null`，缺失和超时单独记录。保留原始采样序列，分别保存目标与实际值。检查掉帧、掉线、最大采样间隔、图像可见性、反馈解码和标定，再交给接收方验证导入。

## 设备静止复测

**ESTUN** 已实测 10 组同编号 TCP 和六关节角，共 20 帧。无漏号、重号或解析错误，平均组间隔约 257 ms。测试方法、CRP 生成和复测命令见 [ESTUN Socket 试验](estun_pose_socket_test.md)。原始日志为 `logs/estun_pose_test_20261116_092258_041216Z.jsonl`。

**OmniHand** 使用当前 COM4、460800 8N1。在倒水程序关闭串口后，从项目根目录运行：

```powershell
& 'D:\Environment\miniconda\envs\Proj\python.exe' -u '.\Orchestrator\omnihand_readonly_test.py'
```

脚本只查询设备版本、产品序列号、十轴实际位置、使能和错误码。位置目标间隔 100 ms，共 30 次，每五次再读一次使能和错误码。检查 `failed_queries=0`，并核对 `logs/omnihand_readonly_*.jsonl` 中的原始发送和接收、采样编号、两个 PC 时钟以及错误字段。

2026-11-16 静止测试中，十轴位置 30/30、使能和错误各 6/6。使能均为 1，错误均为 0。位置平均约 10 Hz，接收间隔 78–125 ms。设备为 O10，软件 1.2.3、硬件 3.0.0。额外查询控制源 `0x81` 超时，其结果不影响所需字段。原始日志为 `logs/omnihand_readonly_20261116_091800_336078Z.jsonl`。

## 完整倒水试采的待接入项

当前 A2C 会在 Phase B 发送位姿后关闭 D435i。试采入口需持续保留录制至回 Home。在控制器上验证真正的并行副任务在运动中可持续上报关节与 TCP，记录工具、坐标系和状态。灵巧手采样与控制共用一条串口，由同一队列顺序执行读写。记录抓放动作中的实际间隔、超时和原始帧。

现有静止试验确认了两边能读取实际反馈。完整倒水过程中三路数据的连续性、对齐和正式导入仍需用同一轮试采验证。控制器的 `OutputCtrl.txt` 可提供任务状态切换和路径完成事件。日志中的 EtherCAT 字段注册和轨迹起点可用于辅助诊断。
